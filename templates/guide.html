User Guide

Agent Handbook

Last updated: September 25, 2026

This handbook tells a project team how the GIABO Digital PMO actually works today: what the 27-role swarm can do, what you can type into Microsoft 365 Copilot or Teams, and which governance rules no one — including the agents — is allowed to change.

Welcome Swarm capabilities Conversational syntax Project tuning

1. Welcome & Overview

GIABO is an autonomous digital employee for project administration. It is not one chatbot with a long prompt. It is a 27-role swarm that routes work to a specialist, writes structured facts into Azure PostgreSQL, and stops for a human when a locked baseline or a PRINCE2 stage tolerance is at stake.

You meet the swarm on two surfaces. They share the same database; they are not the same conversation.

Microsoft 365 Copilot

The declarative agent sets up projects, returns a governance brief, and reports plan usage. It never asks you for a raw tenant or project UUID. Use the conversation starters Set up a new project, Give me the project brief, and Check my usage and billing tier.

Microsoft Teams

Chat with the digital employee to log schedule progress, raise blockers, flag risks, or request a locked-baseline change. The router sends each message to one specialist. A baseline proposal pauses as an Adaptive Card for the human Project Manager (PM Veto).

The swarm’s job is administration: keep RAID current, keep the schedule honest, chase work that is actually overdue, and refuse silent baseline writes. It does not replace the Project Manager. It will not authorize its own change.

2. The Swarm Capabilities

Four capabilities you will feel in day-to-day chat. Everything else in the roster supports them.

P

PMP schedule tracking

Say hours spent and percent complete. The PMP specialist records TaskProgressPayload only. It does not draft a new end date or budget.

A

Agile blocker clearing

Impediments and cross-team waits go to the Agile facilitator. You get a blocker record and a next action item — not a percent-complete write and not a baseline slip.

R

PRINCE2 risk & exception

Budget, scope, timeline, and compliance language is scored against stage tolerance. A true breach raises an exception card. In-tolerance risk is logged, not invented.

C

Dynamic chasing

Outreach is priority-scored, not a daily blast. If someone was contacted in the last 24 hours, the chase is suppressed — even on a critical-path slip.

3. Conversational Syntax & Commands

You do not need slash-commands. Write a normal sentence that contains the facts. The router keys off those facts. Never paste a tenant or project UUID unless you already have one and mean to use it; Copilot is instructed not to ask for them.

Microsoft 365 Copilot

You sayWhat runsWhat you get
Set up a new project plus a short name (and optional SharePoint site or digital-employee name) createProject A project card. Use View Governance Brief on the card to open that project.
Give me the project brief getProjectBrief Markdown of open risks, open actions, and recent swarm audit lines.
Check my usage and billing tier getUsageTelemetry Plan tier, swarm status, project count, and metered spend versus allowance.

Copilot create needs a project name. If you only tap the starter, add a name in the next sentence (for example Set up a new project called Harbour Cutover). If the workspace is not linked yet, Copilot will say so — it cannot invent a tenant.

Microsoft Teams chat

You say (examples)Who answersWhat is written
Logged 6h today; TSK-002 is 40% complete. PMP schedule specialist Task progress only. No baseline edit.
TSK-002 is blocked waiting on Legal to sign the DPA. Agile facilitator Blocker + next action. Not a percent-complete update.
Stage 2 forecast is 15% over the 10% cost tolerance. PRINCE2 governance worker Risk score. Exception card only if the tolerance is actually breached.
Please change the locked baseline end date to 2027-09-01. Change Control Clerk A proposal. The PM must approve the Adaptive Card before anything is written.
not sure, whatever you think (twice) Friction breaker Escalation. The router’s specialist guess is overridden.

Phrases that will not do what you hope

PhraseWhy it fails closed
Asking the Clerk to “check the risk of slipping the date” The Clerk records field/date/budget delta only. Risk discovery is Governance, on a separate turn.
Asking PMP, Agile, or Risk to “just move the baseline” Only the Clerk drafts a PendingChangePayload. Everyone else is read/write-scoped away from baselines.
Approving your own baseline change in chat text Authorization is the PM Veto card, not a typed “approved.”

4. Project Tuning & Customization

You can steer what the swarm works on by how you write. You cannot steer the constitutional rules with a chat message. There is no settings page today that saves chaser aggressiveness or a numeric stage-tolerance slider.

What you can do in conversation

IntentHow to say itWhat actually happens
Name the work Set up a new project called North Pier, SharePoint site … Creates a project row. Optional digital-employee name/email is stored for Outlook/Teams persona.
Point at a document Put the file in the linked SharePoint library Delta ingest caches it and emits DOCUMENT_INGESTED. No extra Copilot command.
Correct a fact Send the updated hours, percent, or blocker in Teams The specialist overwrites its latest payload for that type. History lives in the database, not in the prompt.
Ask not to be chased Reply to a chase (any reply counts as contact) The 24-hour fatigue window starts again. You cannot set that window to 2 hours or 7 days in chat.

Fixed by policy (not tunable)

InvariantWhy it stays fixed
24-hour chase fatigue Score is forced to 0.0 if last contact was under 24 hours, including after a critical-path slip event.
Clerk never evaluates risk Aim 1. The Clerk’s impact line is field/date/budget delta only. Risk questions are illegal on a slip event.
Proactive agents never draft baselines Aim 2. A governance wake after BASELINE_SLIP_REQUESTED classifies RAID. It does not edit the pending change.
PM Veto is not bypassed Aim 3. Sibling event-bus runs do not resume a paused veto. Reject does not auto-redraft.
Stage tolerance is classified, not bargained Governance sets prince2_exception_triggered from the facts you gave. There is no “set my tolerance to 20%” setting in chat.
Free trial vs Standard-tier agents Risk Radar and Scrum Master Liaison stay denied on free_trial. That is a plan gate, not a prompt.
Billing halt outranks everyone A used-up trial or held paid workspace never reaches Azure OpenAI, including proactive wakes.

If you need a different fatigue window or a persisted tolerance table, that is a product change — not something the digital employee can grant itself. Until then, be precise in the message (task id, hours, percent, the locked field you want changed) and let the human PM use the card.
